# Project 2 — Personal Expense Tracker

## Client Background

A freelance graphic designer manages all income and expenses manually using a notebook.

As the number of transactions has increased, keeping track of daily spending has become difficult. Calculating monthly expenses, finding previous transactions, and correcting mistakes now takes a significant amount of time.

The client wants a console-based application that can organize financial records and make it easier to monitor personal finances.

You have been hired to build this application.

---

# Project Objective

Develop a menu-driven console application that allows users to record, organize, and review their financial transactions.

The application should make it easy to manage daily income and expenses while providing useful financial summaries.

The program should continue running until the user chooses to exit.

---

# Functional Requirements

Your application should allow users to perform the following operations.

### 1. Add Income

Allow users to record a new income entry.

Each record should include information such as:

- Source
- Amount
- Date

---

### 2. Add Expense

Allow users to record a new expense.

Each expense should include information such as:

- Category
- Description
- Amount
- Date

---

### 3. View All Transactions

Display every income and expense recorded in the application.

The information should be presented in a clear and readable format.

---

### 4. Search Transactions

Allow users to search for transactions.

You may decide the search criteria.

Examples include:

- Category
- Date
- Description
- Amount

---

### 5. Update Transactions

Allow users to modify previously recorded transactions.

The user should be able to choose which information needs to be updated.

---

### 6. Delete Transactions

Allow users to remove unwanted transactions from the system.

The application should clearly indicate whether the operation was successful.

---

### 7. Financial Summary

Display useful financial information such as:

- Total Income
- Total Expenses
- Current Balance

You may include additional summaries if you think they would be useful.

---

### 8. Exit Application

Allow users to safely close the application.

---

# Client Requirements

The client has provided the following expectations.

### Accurate Financial Records

Incorrect financial information can lead to poor decisions.

The application should help users maintain accurate records by preventing invalid information from being stored.

---

### Reliable User Experience

The application should continue running even if users accidentally enter incorrect information.

Instead of terminating unexpectedly, the program should explain the problem and allow the user to try again.

---

### Clear Navigation

Users should always know what options are available.

Every operation should return to the main menu after completion.

---

### Organized Output

Display all financial information using a consistent and easy-to-read format.

The client should be able to quickly understand the displayed information.

---

### Easy Maintenance

The client expects the application to be organized in a way that allows future features to be added with minimal changes.

---

# Technical Expectations

Before writing your program, think carefully about the application's design.

Consider questions such as:

- How should financial records be organized?
- How will users identify a specific transaction?
- How will duplicate or incorrect information be handled?
- How can the application recover when users make mistakes?
- How can repeated code be minimized?

Plan your solution before writing code.

---

# Development Guidelines

While developing the application:

- Build one feature at a time.
- Test every feature before adding the next one.
- Keep your code organized.
- Write meaningful variable and function names.
- Display helpful messages for every operation.
- Think about how real users would interact with your application.

Remember:

A professional application not only performs calculations but also handles unexpected situations gracefully.

---

# Deliverables

Your final submission should include:

- A menu-driven console application.
- All required features.
- Well-organized code.
- Clear user interaction.
- Proper handling of invalid user input.
- Readable output formatting.
